# IIC 驱动模块开发规范

## 1. 模块职责

IIC 驱动管理一条 I2C 总线及其设备对象，提供异步主机写、写后读、两段写、忙状态和波特率控制，并保留从机 7 位/10 位寻址、从机寄存器映射和从机完成事件能力。引脚复用、开漏和上下拉由 PORT 模块配置；总线恢复可临时切换引脚为 GPIO，但必须在恢复后还原 IIC 复用。

## 2. 通用框架来源与继承要求

`demo/drv_iic.h`、`demo/drv_iic_cfg.h` 和 `demo/drv_iic.c` 必须以当前仓库的 IIC 参考框架为基准，完整保留以下内容：

- `TDrvIicOpResult`、`TDrvIicSlaveEvent`、`TDrvIicMode`、`TDrvIicSlaveAddr`、`TDrvIicSlaveMemAddrWidth`；
- `TDrvIicDevItem`、`TDrvIicDev`、`TDrvIic` 和从机寄存器映射成员；
- 设备层和总线层全部公开接口、枚举数值、回调类型、引用计数、设备槽位和对象生命周期；
- `TDrvIicCfg` 的 SCL/SDA 端口、引脚、复用及实例编号成员。

目标 MCU 没有对应的寄存器、时钟、DMA、IRQ 或引脚恢复机制时，demo 必须保留接口和对象字段，以 TODO 说明所需手册信息；不能为迁就目标芯片删减现有框架。平台实现是否完整支持从机模式，应在完成硬件能力评估后决定。

## 3. 必要接口范围

- 设备层：`TDrvIicDevCreate/Destroy/Open/Close`、波特率设置和读取、异步写后读、两段写、忙状态查询；
- 总线层：`TDrvIicCreate/Destroy/Open/Close`、模式/从机地址/从机寄存器映射设置、波特率设置和读取、从机映射读写、忙状态查询；
- 设备层的 `OnComplete` 与总线层的 `OnSlaveComplete` 回调。

不在未确认需求时增加 SMBus、DMA、目标地址列表、主机多地址监听或额外同步传输接口。

## 4. 开发与评估顺序

1. 先完成通用 demo，保留当前参考驱动的完整头文件接口、配置结构和对象模型；所有硬件相关实现使用 TODO。
2. 从用户手册确认实例数量、I2C 标准/快速模式范围、7 位/10 位主从地址、重复起始、ACK/NACK、STOP、仲裁、总线错误、时钟拉伸、滤波、低电平超时、FIFO/DMA 和中断状态清除语义。
3. 从芯片头文件核对寄存器、位域、IRQ 编号、时钟和复位位；从 SDK 示例核对启动、寻址、收发、重复起始和错误恢复顺序，但平台代码不调用 SDK I2C 封装函数。
4. 逐项比较硬件能力与参考框架：主机异步状态机、两段写、写后读、从机 7/10 位寻址、寄存器映射从机、回调时机、引用计数和多设备排队。
5. 若硬件无法无损实现已有公开语义，先列出差异和可选适配策略，等待确认后再建立平台实现。

## 5. 寄存器级实现规则

- 平台代码只使用芯片头文件的寄存器/位域宏和 CMSIS NVIC 接口，不调用厂家 `i2c_*()` 封装函数。
- 每个状态等待都必须有超时，并将 NACK、仲裁丢失、总线错误、引脚低超时、总线忙、START/STOP 失败映射为既有 `TDrvIicOpResult`。
- 主机写后读必须按手册实现 START、地址+写、写数据、重复 START、地址+读、ACK/NACK 与 STOP 的精确顺序；最后一字节读取的 ACK/NACK 时序必须单独核对。
- 多设备共享同一总线时，设备对象只能在父总线空闲时发起事务；完成或失败时清除 `busy_` 并仅回调当前设备。
- 从机模式下，地址匹配、接收、发送、STOP/重复 START、错误和缓冲区边界都必须由状态机分别处理；不得在 ISR 中越界访问从机映射或整寄存器清除其他状态。
- 进行 GPIO 总线恢复前确认 IIC 外设已关闭；最多输出的恢复时钟数、SCL/SDA 采样及复用恢复顺序以手册为准。

## 6. 验证清单

- [ ] 7 位主机写、读、写后读、仅写、仅读和两段写；
- [ ] NACK、仲裁丢失、总线错误、低电平超时、总线忙、START/STOP 超时；
- [ ] 多设备引用、重复 Open/Close、并发发起和回调后的下一事务；
- [ ] 7 位/10 位从机寻址、寄存器地址解析、映射读写、STOP 与重复 START；
- [ ] GPIO 总线恢复后 IIC 复用、开漏和上拉恢复正确；
- [ ] 所有 IRQ 状态按手册精确清除，且所有轮询均有超时。
