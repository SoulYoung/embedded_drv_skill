# XcuSPI 驱动模块开发规范

## 1. 模块职责

XcuSPI 是主控制器通信用的 SPI 从机协议驱动，管理双缓冲数据项、DMA 收发、请求信号、超时和错误恢复。

## 2. 必要接口

- `TDrvXcuSpiCreate/Destroy/Open/Close`
- `TDrvXcuSpiReadable/Read/FreeSize/Write/Commit/Reset`
- `TDrvXcuSpiSetTimeout`

当前头文件中的全部 XcuSPI 接口均为必要接口；目标 MCU缺少对应 SPI 从机、DMA 或请求信号能力时，保留接口与状态机，并由硬件 `TODO` 返回现有错误码。

## 3. 协议骨架、平台适配与公共资源

XcuSPI 的数据项、报文组织、双缓冲状态、接口调用顺序和回调语义是协议骨架。移植或维护时，应以同类参考实现为该骨架的基线，完整保留公开类型、对象成员、状态迁移、错误码模式、函数注释和调用顺序；不得仅为适配新硬件而删除核心协议结构或改写既有语义。

平台适配只承担外设实例、板级引脚、时钟、数据搬运、请求信号和完成来源的落地。demo 中必须保留协议数据结构、状态机和完整注释；平台相关操作以 `TODO` 表示，并说明需要完成的动作、前置条件或完成条件，不得把具体寄存器、SDK 调用或固定硬件数值写入 demo。

SPI 的多个角色应共享按实例索引的公共资源描述。XcuSPI 在创建阶段绑定该描述，而不维护仅供自身使用的私有基址表或实例映射函数；这样新增另一 SPI 角色时，可复用一致的实例和板级资源定义。

## 4. 状态、DMA 与回调规则

1. `Write` 仅填充当前空闲项，`Commit` 才提交给状态机；`Read` 仅消费已完成项。每个数据项的状态迁移及其所有者必须清晰且可追溯。
2. 临界区只保护双缓冲索引、项状态和忙状态等共享状态转换。DMA 描述准备、外设配置和可能耗时的硬件步骤应在临界区外完成。
3. 启动传输时，先完整准备本次数据项和数据搬运参数，再按目标平台规定的顺序使能搬运与外设请求，随后发布传输状态、启动超时并发出协议握手。顺序的硬件部分由手册确认，协议状态发布不得早于其所依赖的资源就绪。
4. 收发方向分别完成时，每个回调只收口本方向的请求和完成状态；只有满足协议定义的最终完成条件才交付数据项。发送搬运完成不当然代表总线传输已经结束，最终完成来源必须由目标手册和接口语义确定。
5. DMA 或中断回调遵守既有接口约定的上下文，只执行必要的状态更新和通知。会与在途传输竞争的恢复操作由安全的后续上下文执行。

## 5. 复位、超时与错误处理

`Reset(false)` 的语义是只在当前事务已经静止时恢复。无法证明静止时，函数不得改动硬件、DMA、握手或双缓冲状态。`Reset(true)` 才可执行强制收口：撤销请求、停止或收口数据搬运、清理外设状态并恢复协议缓冲。具体静止条件、停止方式及清理顺序由目标 MCU 的资料确定，不能无依据地复制另一平台的 DMA 判断或复位步骤。

超时和异常回调只报告错误、结束本方向的等待条件并通知恢复路径；恢复路径再调用对应的复位流程。公开的结果码接口以成功值初始化 `result`、保持单一出口，返回错误时使用项目日志机制报告。查询数量或可读状态的接口保持其既有返回语义，私有无失败语义的辅助函数不额外制造错误码。

## 6. 验证清单

- [ ] 双缓冲满、空、连续收发和异常中断下状态转换正确。
- [ ] 收发两个方向以不同先后完成时，只有满足最终完成条件才交付数据项。
- [ ] 单方向 DMA 错误、超时和强制复位后均可恢复重新传输。
- [ ] 非强制复位在传输未静止时不产生硬件或协议状态副作用。
- [ ] 请求信号、片选时序和最终完成条件符合目标协议与目标平台资料。
- [ ] demo 保留完整协议骨架，所有平台适配点均有可执行的 `TODO` 说明。
