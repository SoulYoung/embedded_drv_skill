# TimerSrv 驱动模块开发规范

## 1. 模块职责

TimerSrv 提供软件定时项、系统节拍和高性能自由运行计数读取；它不是普通定时器外设的直接抽象。

## 2. 必要接口

- `TDrvTimerSrvCreate/Destroy/Open/Close`
- `TDrvTimerItemInterval/SetInterval/Start/Stop`
- `TDrvTimerSrvCreateTimer`
- `DrvTimerSrvGetHighPerformanceCounter`

当前头文件中的全部定时服务接口均为必要接口。目标没有适合的自由运行计数器时，仍保留高精度计数接口并在 `TODO` 中返回确定的零值/错误语义。

## 3. 实现规则

1. 根据手册选定稳定节拍源，配置计数周期、溢出和中断确认。
2. 定时项管理、到期判定和节拍累加保留在软件框架中；只把底层计数器访问放在 TODO。
3. 高性能计数接口必须返回频率、当前值和最大值，不能假设固定计数器位宽。
4. 必须确认周期寄存器的实际计数语义。若硬件从重装值倒数到0后产生事件，一个周期包含“重装值 + 1”个时钟周期；目标实现应按 `reload = clock / tick_hz - 1` 配置，并明确时钟不能整除时的拒绝或取整策略。
5. 高性能时间必须使用一致快照：连续读取“软件tick—当前计数—软件tick”，同时检查硬件超时标志；两次tick相同且无Pending时才返回样本。最大值来自重装寄存器，已耗计数由“重装值 - 当前值”换算。
6. 定时器服务的定时项索引和数量会被创建接口与节拍ISR共同访问，创建新定时项时直接使用项目既有的全局IRQ嵌套保护。默认认为每个 TimerItem 由一个调用方独占，启停和改周期接口不额外加锁；确有同一对象跨线程共享的需求时，由调用方负责同步。
7. 现有接口规定 `OnTimer` 在ISR中调用，这是本模块的既有例外。回调不得阻塞、等待、动态分配或记录日志；应控制所有已启用回调的总执行时间。
8. Open必须校验时钟频率和reload范围；时钟、控制器和NVIC任一步失败都要按相反顺序回退。每次成功Open开始新的tick时间基准。

## 4. 验证清单

- [ ] 多定时项启停、周期修改和边界周期正确。
- [ ] 节拍溢出后到期判定正确。
- [ ] 高性能计数频率与实际时钟一致。
- [ ] 周期寄存器的实际周期与目标1ms误差符合“重装值 + 1”计数规则。
- [ ] 在溢出边界连续读取高性能时间，不出现tick与子毫秒计数错配或倒退。
- [ ] 创建定时项与ISR交错执行时，不发生重复分配或损坏定时项索引。
