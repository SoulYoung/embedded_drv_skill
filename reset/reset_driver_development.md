# Reset 驱动模块开发规范

## 1. 模块职责

Reset 驱动负责读取、保存和清除复位原因，并触发目标 MCU 支持的系统复位。它不负责外设局部复位；外设复位由 Clock 等对应模块管理。

## 2. 必要接口

- `TDrvResetCreate/Destroy`
- `TDrvResetOpen/Close`
- `TDrvResetGetReason`
- `TDrvResetClrFlags`
- `TDrvResetTrigger`

用户未明确提出其它能力时，不增加特殊接口。

## 3. 实现规则

1. 根据用户手册把原始复位状态位显式映射为 demo 中数值稳定的通用原因位；没有对应硬件原因时不置位，不能为省略映射而修改公开枚举值并直接返回原始寄存器。
2. `Open` 时一次读取并保存最近一次复位原因，避免后续初始化清除硬件标志后丢失信息；多个同时置位的原因必须全部保留。
3. 明确 `GetReason` 返回“Open 时快照”还是“硬件实时值”。采用快照模型时，`ClrFlags` 只清硬件锁存位且不修改快照；若接口需要清快照，应另行明确语义，不能让同一接口前后含义漂移。
4. 清除标志必须采用手册规定的访问语义；可能是写一清零、写零清零、独立清除寄存器或特定命令，不能假定所有芯片都采用同一种方式。
5. `Destroy` 先兜底 `Close`，最后再写 Destroy 状态，避免 Close 覆盖最终生命周期标记。
6. 触发复位前检查对象状态和触发模式；使用内核复位接口时确认必要屏障，并将成功路径视为不返回流程。

## 4. 验证清单

- [ ] 上电、软件、看门狗、低压和外部复位等实际支持原因映射正确。
- [ ] 原因在 Open 后可读取，清除后状态符合手册。
- [ ] 未 Open、非法类型和空指针返回确定错误码。
- [ ] 触发复位接口不会误写其它复位或低功耗控制位。
- [ ] 公开原因位数值与 demo 一致，原始寄存器到公开位掩码的映射有逐位依据。
- [ ] 清除操作符合目标寄存器访问属性，清除硬件标志后快照行为与接口文档一致。
- [ ] 打开状态下 Destroy 后最终状态确实为 Destroy，而不是被 Close 覆盖。
