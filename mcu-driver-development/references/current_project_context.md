# MCU 驱动开发续接上下文

本文件记录当前驱动标准化工作的已确认结论和工作状态。新对话开始处理本仓库中的驱动任务前，先阅读 `SKILL.md` 与本文件；再按任务读取对应模块 demo、芯片手册、官方 SDK 示例和必要的用户参考实现。

## 1. 仓库与资料边界

- 一个 MCU 平台对应一个独立驱动仓库；不为多个 MCU 共仓设计兼容层。
- 新平台实现的必备资料顺序为：模块 demo、芯片用户手册、官方 SDK demo/头文件。demo 决定项目接口、对象模型、命名、注释和格式；手册决定硬件真相；SDK 用于核对配置顺序与寄存器宏。
- 用户额外提供的 `user/` 同模块实现是补充参考。存在时必须完整对比其 `.h` 与 `.c`，继承公开接口、枚举数值、成员名、调用顺序、注释和格式；只修正可验证问题。
- 厂家 SDK 头文件可用于寄存器基址、寄存器和位域宏。除非用户明确要求，不调用厂家 `xxx_init`、`xxx_config`、`xxx_enable`、`xxx_get` 等包装函数。
- 本平台的共享对象、基础类型、公共错误码和芯片头文件放在 `drv_common.h/.c`。`drv_common.h` 只包含有共享数据或直接依赖关系的驱动头；模块 `.c` 通常只包含自身 `.h` 与 `drv_common.h`。

## 2. 全局代码规范

- C、头文件、脚本与文档使用 UTF-8。
- 可失败的公开 C 接口使用 `result` 和单一 `return result;` 出口。
- `if/else` 单条语句不加花括号；两条及以上语句换行并加花括号。
- 文件级 Doxygen、修改日志和版权信息仅放在模块 `.h`；`.c` 直接从自身 `.h` 开始。保留 Doxygen 类型/接口注释和历史名称；不要为了抽象而重命名或删减枚举。
- 公开接口在自己的 `.h` 中按“必要接口”“特殊接口”分组。用户未明确要求时优先仅实现必要接口；特殊功能直接放在该 `.h`，不另建扩展层或能力查询层。
- Destroy 的目的仅为兜底 Close：对象已打开时调用 Close，但不依据 Close 的结果改变 Destroy 成功路径。
- 父对象一般使用项目已有引用计数模型；子对象可以使用 `is_open_`。已有同模块参考若采用不同模型，保持其模型。
- `switch` 默认按全局规范；Clock 模板例外：每个 `case`/`default` 有独立语句块，`break` 位于语句块后。

## 3. 文档与 demo 规则

- `doc/<module>/` 放模块开发文档及 `demo/drv_<module>.h/.c`；需要配置文件时加 `drv_<module>_cfg.h`。
- demo 的 `.h` 必须以当前 AC78428 驱动的接口外形、完整注释、对象模型和格式为基准，而不是以某次新 MCU 实现为基准。
- demo 的 `.c` 保留可直接复用的生命周期、参数检查、引用计数和纯框架逻辑；寄存器、时钟、复用、DMA、IRQ 路由等与 MCU 有关的代码必须以 `TODO` 标记，并说明要查阅的手册/SDK 信息。
- demo 不得出现新平台的 SDK 宏、SDK 函数、寄存器名或具体 MCU 名称。

## 4. 已建立模块

- `doc/adc/`：ADC 文档和 demo（含 `drv_adc_cfg.h`）。
- `doc/clock/`：Clock 文档和 demo；寄存器级补充规则在 `references/clock_register_level.md`。
- `doc/wdog/`：WDog 文档和 demo。
- `doc/irq/`：IRQ 文档和 demo。
- `doc/port/`：PORT 文档和 demo。
- `doc/gpio/`：GPIO 文档和 demo。

### Clock 已确认规则

- 寄存器级实现，不调用厂家 `rcu_*` 包装函数。
- 若启动阶段系统时钟已经完成 PLL 切换，不重复重新配置，适配 Boot/App 场景。
- 枚举中的“寄存器组 × 32 + 位号”编码完整保留，不改为厂家枚举或映射表。
- 私有函数按调用顺序放置；不为仅单处调用的短小逻辑额外拆函数或集中声明原型。

### IRQ 已确认规则

- 职责仅限全局中断嵌套控制和 NVIC 独立中断开关；不负责外设 Pending、ISR 注册、优先级和向量表。
- 全局中断使用 `global_ref_`：0→1 时禁用，1→0 时恢复；必须阻止下溢和 `Int8` 上溢。
- 可用 CMSIS `NVIC_EnableIRQ`、`NVIC_DisableIRQ`、`__enable_irq`、`__disable_irq`。这些不是 GCC 专用接口；IAR 的 CMSIS 会映射为 IAR intrinsic。

### PORT 已确认规则

- PORT 只管理引脚模式、复用、上下拉和开漏等配置，不负责 GPIO 电平和 GPIO 输入中断。
- 通用 demo 已移除 `TDrvPortSetStrength` 与 `TDrvPortSetInputFilter`：它们的语义过分依赖 MCU，应在确有明确、可表达的需求时作为特殊接口加入。
- 修改模式、复用、上下拉等共享寄存器时，只改目标字段并写回；必要时使用 IRQ 临界区。

### GPIO 已确认规则

- GPIO 只管理电平读写和 GPIO 输入中断对象；PORT 先完成引脚模式、复用和上下拉。
- GPIO 输入中断是一种模块能力，不假定所有 MCU 都有独立名为 EXTI 的外设。实现时按手册确定 GPIO 内部中断、独立 EXTI 或其他路径。
- 单引脚写电平优先使用芯片提供的原子置位/清零寄存器。
- 若同号引脚跨端口共用中断源，冲突对象必须拒绝打开；若多个线共用 NVIC 向量，按向量组管理开关。
- Pending 按手册规定精确清除，不得整寄存器清零。

### WDog 已确认规则

- 先按手册确定独立看门狗或窗口看门狗；默认通用对象只实现一个明确的硬件对象。
- 硬件复位后默认使能不等于驱动对象已经打开；驱动生命周期以对象状态为准。硬件允许重配置时，Open 应先解锁、失能默认运行状态，再写入本次配置并重新使能。
- 在临界区外完成频率读取、超时/窗口校验和寄存器镜像计算；临界区仅覆盖解锁、失能、连续寄存器写、重新使能、锁定和首次服务。解锁状态轮询仅在手册明确要求时使用。
- 启动后不能软件停止的硬件，Close/Destroy 只改变对象状态，不虚构关闭动作或关闭它仍依赖的时钟。
- 解锁、配置和喂狗序列直接用寄存器完成；连续喂狗及低功耗切换的时序限制必须记录到平台文档。
- WDog demo 与平台内部配置完整保留 AC78428 的 `TDrvWDogCfgExTag` / `TDrvWDogOpMode` 框架；目标芯片无对应能力时保留成员并使用 TODO 或平台注释说明。

## 5. GD32E535 当前产物与复核点

`gd32e535/` 中已生成 `drv_clock.*`、`drv_irq.*`、`drv_port.*`、`drv_gpio.*`、`drv_wdog.*`，并有 `drv_common.*` 和资料目录。

- Clock 已多轮按用户参考实现调整，用户反馈“基本符合要求”。
- IRQ 已按芯片头文件确认外设 IRQ 编号范围 0–114，直接使用 CMSIS NVIC 与全局中断接口；用户反馈“大致没问题”。
- PORT/GPIO 已验收完成。
- WDog 已以 FWDGT 实现：使用 40 kHz IRC40K、/4096 预分频、12 位递减计数器和寄存器级解锁/更新/喂狗序列；`timeout` 单位为 s，支持 1 至 128 s，装载值按向上取整计算以保证不早于请求时间超时。FWDGT 启动后无法软件停止，Close/Destroy 只关闭对象状态。
- WDog 已验收通过。
- `gd32e535/drv_common.h` 已集中包含公共头和存在直接依赖关系的驱动头；独立模块不应仅为方便而加入。模块 `.c` 不重复加芯片 SDK/错误码头。

## 6. 当前待办与建议顺序

1. IIC：已建立 `doc/iic/` 开发规范及 GD32E535 兼容性评估。AC78428 公开框架可继承；实现前确认 I2C 100 kHz/400 kHz 的板级上升/下降时间或保守默认时序参数。
2. 若用户提出新模块，先在 `doc/<module>/` 建开发文档与通用 demo，再用新芯片的手册、SDK 和头文件生成该平台代码。
3. 每次从用户反馈中提炼出真正跨模块或模块专用的稳定规则，分别补入 `SKILL.md`；不要把一次性芯片细节泛化成全局规则。
4. 每次更新 Skill 后执行 `quick_validate.py`；每次改代码后至少执行文本检查与 `git diff --check`。若环境资料不完整导致不能编译，明确说明未做编译验证的原因。
