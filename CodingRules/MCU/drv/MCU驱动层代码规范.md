# MCU 驱动层代码规范

## 1. 适用范围与层级契约

本规范适用于任意 MCU/SoC 的片上外设驱动：时钟、复位、GPIO、DMA、定时器、串口、SPI、I2C、CAN、ADC、Flash、看门狗和中断控制器等。驱动层的唯一职责是将芯片参考手册定义的硬件能力转换为稳定、可移植到上层的 C 接口。

驱动层可以依赖芯片厂商 SDK、CMSIS、寄存器定义和基础运行库；不得依赖产品型号、板卡引脚分配、外设器件型号或业务逻辑。更换 MCU 时，允许替换本层实现；上层的接口语义、配置模型和错误语义应尽量保持稳定。

## 2. 文件和接口边界

- 全部 C、头文件与文档使用 UTF-8；文件名小写下划线分词。建议使用 `drv_<module>.c/.h`，配置声明使用 `drv_<module>_cfg.h`。
- 每个 `.c` 首先包含自身公开头文件，再包含本层公共头、SDK/CMSIS 和基础库。公开头文件只暴露调用方必需的类型、配置和 API；寄存器映射、私有状态机、SDK 类型和私有辅助函数留在 `.c`。
- 公开头使用 Doxygen 文件头、唯一 include guard、`extern "C"`。guard 应由层级与模块名构成，如 `_DRV_UART_H_`。
- 新驱动至少定义：初始化/反初始化或 Create/Destroy、使能/停用或 Open/Close、业务操作 API；需要异步事件时定义回调注册或中断通知 API。

## 3. 命名与数据建模范式

项目可沿用既有前缀；若新建统一风格，推荐如下规则：

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 公开类型 | `TDrv` + 模块 PascalCase | `TDrvUart` |
| 配置类型 | 类型名加 `Cfg` | `TDrvUartCfg` |
| 常量/枚举项 | `kDrv` + 模块 + PascalCase | `kDrvUartTimeout` |
| 公开函数 | `TDrv` + 模块 + 动词 | `TDrvUartOpen` |
| 私有函数 | 同一模块前缀且 `static` | `TDrvUartDoOpen` |
| 文件内静态对象 | `g_drv_` + 小写模块名 + `_` | `g_drv_uart_cfg_` |
| 私有成员 | 小写下划线并以 `_` 结尾 | `cfg_`、`open_ref_` |

配置数据与运行状态必须分离：调用方提供的配置以 `const` 保存且不得修改；驱动私有状态包含基址、引用计数、传输状态和回调上下文。多实例差异使用“逻辑实例索引 → 私有硬件描述表”的映射处理，禁止将某个实例的地址或引脚硬编码在公共 API 中。

## 4. 生命周期、资源与状态机

- 所有资源获取必须有对称释放：Create/Init 对应 Destroy/Deinit，Open/Enable 对应 Close/Disable，申请中断对应注销中断，开启时钟对应关闭时钟。
- 重复调用的生命周期接口要么明确幂等，要么以引用计数实现；两者必须在头文件说明。首次打开才执行硬件初始化，最后关闭才撤销硬件资源。
- 资源状态须显式保存并校验，例如 `created`、`opened`、`busy`、`tx_pending`。禁止仅凭硬件寄存器偶然状态推断对象是否可用。
- Create/Open 失败时必须回滚已获得的资源，使对象回到可重试或可销毁状态。Close/Destroy 应能安全处理未完全打开或部分初始化的对象。
- 状态机的事件、状态、转移条件和完成/失败出口要可追溯；中断服务函数只推进状态机或记录事件，耗时处理交由线程/任务上下文完成。

## 5. 函数、错误与控制流

- 公开可失败接口采用单出口：声明 `result`，按“参数 → 对象状态 → 硬件/传输”顺序赋值，最后唯一 `return result;`。`void` 接口不返回值。
- 使用项目统一的整数、布尔和错误码类型；禁止在同一模块混用多套类型系统。成功、参数错误、状态错误、超时、通信错误和硬件错误应可区分，禁止以裸 `0`/`-1` 替代错误码。
- 在访问对象成员、输出指针、配置、实例索引、缓冲区或回调前完成空指针与范围检查。长度和地址范围检查必须防止 `offset + size` 溢出。
- 轮询硬件状态必须带明确超时或次数上限；超时转换为错误码。禁止无限循环、无条件忙等和在中断上下文长时间延时。
- 私有辅助函数可使用 `static inline`；除明确的 API、ISR 入口和链接期注册符号外，文件级函数和数据均使用 `static`。

```c
Int32 TDrvXxxOpen(TDrvXxx *self)
{
    Int32 result;

    if (self == NULL)
        result = kDrvErrorParam;
    else if (!self->created_)
        result = kDrvErrorState;
    else
        result = TDrvXxxDoOpen(self);

    return result;
}
```

## 6. 寄存器、中断与并发

- 寄存器访问仅使用经验证的 SDK/CMSIS 定义、寄存器结构或本项目封装的读改写宏；禁止魔法地址和无出处位掩码。命令、位域、超时和时钟频率均使用具名常量。
- 对读改写敏感的寄存器使用芯片规定的原子置位/清零寄存器或受保护的读改写。写一个字段时不得破坏同寄存器其他字段。
- 共享的引用计数、环形队列、完成标志和回调指针必须采用与平台一致的临界区、原子操作或锁保护；临界区只包围最小临界数据，退出临界区后再回调。
- ISR 中不做阻塞传输、动态分配、日志格式化或用户回调。ISR 清中断源、保存必要数据、唤醒/置位后退出；回调在允许的上下文中执行。
- DMA、缓存和内存屏障遵循目标架构要求：描述符对齐、缓冲区可访问性、缓存清理/失效以及传输完成后的可见性必须在注释或封装层明确。

## 7. C 语言书写风格（强制）

### 7.1 排版与文件布局

- 缩进固定为 4 个空格，不使用 Tab；一行最多建议 120 列。超长函数调用在逗号后换行，并使后续参数对齐到第一个参数。
- 左花括号独占一行；右花括号单独占一行，`else`、`while`（`do...while`）与前一右花括号同行。所有控制语句后必须有一个空格：`if (`、`for (`、`while (`、`switch (`。
- 指针星号跟随类型：`UInt8 *buf`、`const TDrvCfg *cfg`；一行只声明一个指针变量，避免 `UInt8 *a, b;`。
- 文件内顺序固定为：文件注释/包含 → 宏 → 常量枚举 → 私有类型 → 静态数据 → 私有函数前置声明 → 公开函数 → 私有函数/ISR。函数之间空一行；逻辑阶段之间空一行。
- include 不得依赖间接包含。头文件内使用的每个公开类型必须显式包含其定义头，或以受控前置声明解决。

### 7.2 `if/else` 与条件表达式

- `if`、`else if`、`else` 分支仅包含一条语句时，**不得**使用花括号；包含两条及以上语句时，**必须**使用花括号。该规则同样适用于资源、状态和硬件寄存器相关分支。
- 条件按“空指针 → 边界 → 状态 → 具体业务条件”书写；不要在一个条件中混合赋值、函数副作用和复杂计算。复杂条件先拆为具名 `Bool` 局部变量。
- 常量放在右侧，采用自然比较：`if (count == 0U)`；布尔值用 `if (ready)` / `if (!ready)`，不写 `if (ready == True)`。
- 条件链表达互斥的错误优先级：参数错误、状态错误、资源错误、传输/硬件错误。每个分支只完成一个决策。

```c
if (self == NULL || buf == NULL)
    result = kDrvErrorParam;
else if (!self->opened_)
    result = kDrvErrorState;
else
{
    TDrvXxxPrepareTransfer(self);
    result = TDrvXxxDoTransfer(self, buf, size);
}
```

### 7.3 `switch`、循环与跳转

- `switch` 仅用于同一枚举或离散整型值分派；每个 `case` 均换行、缩进并以 `break;` 结束。需要局部变量时，使用 `{}` 包围该 `case`。
- 禁止无注释贯穿（fall-through）。确有需要时，在贯穿位置写 `/* fall through */`，并确保后续 `case` 不依赖未初始化变量。`default` 必须存在：对外部输入返回参数错误；对已验证枚举保留断言/安全退出，且不得访问硬件。
- `for` 用于可计数的循环，`while` 用于状态驱动循环；循环体多于一条语句必须加花括号。循环计数器使用无符号类型时，禁止依赖 `i >= 0` 退出。
- 禁止 `goto`，除非项目规定统一的清理标签模式；本规范优先用单出口、状态变量和对称释放实现清理。禁止在 `if`/循环条件中递减超时计数导致可读性下降。

```c
switch (cfg->mode)
{
case kDrvModePolling:
    result = TDrvXxxDoPolling(self);
    break;

case kDrvModeInterrupt:
    result = TDrvXxxDoInterrupt(self);
    break;

default:
    result = kDrvErrorParam;
    break;
}
```

### 7.4 类型、常量、宏与初始化

- 数值字面量按类型添加后缀：无符号整数使用 `U`，长整型按项目类型规则使用 `UL`；位操作使用明确宽度的常量，禁止以有符号 `1 << bit` 构造掩码。
- 常量优先使用匿名 `enum` 或 `static const`；仅当需要编译期条件、类型泛化或寄存器访问封装时使用宏。宏必须全大写、参数和整体加括号、不得评价参数多次；禁止用宏代替有类型的普通函数。
- 枚举首项显式赋值为 `0U`；存在“无效/最大值”时使用 `kXxxInvalid`、`kXxxMax`。公开枚举不得依赖编译器默认大小或任意调整已有数值。
- 结构体采用指定成员初始化；静态数组长度使用 `sizeof(array) / sizeof(array[0])` 或项目已有宏。局部变量在声明时初始化，未使用变量不得保留。
- 类型转换必须显式且缩窄前先做范围检查；指针与整数互转仅限 SDK 规定场景，并集中在硬件访问封装内。

### 7.5 注释、日志与函数规模

- `//` 用于简短行内说明，`/** ... */` 用于公开 API 和类型。注释解释约束、单位、顺序、数据手册依据或异常原因，不复述显而易见的代码。
- 公开函数注释至少包含用途、`self` 生命周期要求、输入/输出参数、单位、可在何种上下文调用和返回值；写寄存器前说明该写入为何安全。
- 单个函数宜只做一件事；超过约 80 行、嵌套超过 3 层或同时处理协议/状态/资源三类逻辑时，应拆为私有函数。日志不得处于 ISR、轮询内层或每字节路径。

### 7.6 生成或重构后的强制复核

- 新生成、批量修改或重构任一驱动后，必须对正式源码、公开头文件及该模块 demo 执行全文件复核；不得仅检查本次修改附近的代码。
- 复核时逐项确认：控制语句的条件、语句和花括号不同行；不存在压缩式单行分支、同行花括号，或一行连续多条语句的写法。
- 优先通过调整函数定义顺序消除私有函数前置声明。仅当 C 的调用依赖或固定 ISR、链接入口确实无法通过重排解决时，才保留最小范围的前置声明，并在声明处说明原因。
- 完成格式复核后，再检查每个公开可失败函数仍只有一个 result 出口；格式整改不得改变参数校验顺序、资源获取顺序、错误码和失败回退语义。
- demo 必须能够独立表达当前对象生命周期和错误回退模型；正式实现变更父子对象、引用计数或并发策略时，demo 与模块工作流必须同步更新。

## 8. 可测试性

- 将可替换的硬件访问、时间源和回调抽象为小接口，便于单元测试。测试至少覆盖参数错误、生命周期非法顺序、超时、并发竞争和正常完成路径。
- 对寄存器写序、资源回滚和状态机转移建立 Mock/桩验证；每个修复过的边界缺陷应增加可复现测试。

## 9. 生成前检查清单

1. 是否只依赖 MCU SDK/寄存器定义，未混入板型、外设器件或业务策略？
2. 公共接口是否与硬件型号无关，实例差异是否收敛到私有映射表？
3. 每项资源是否有成对释放，失败路径是否完整回滚？
4. 是否所有可失败 API 均单出口、参数先检、错误码可区分、等待有超时？
5. 是否正确处理寄存器读改写、IRQ/并发、DMA/缓存与 ISR 上下文限制？
6. `if/else`、`switch`、循环、类型转换、宏和初始化是否满足第 7 章？
