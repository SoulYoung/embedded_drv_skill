# ADC 驱动模块开发规范

## 1. 模块目标

ADC 驱动向上提供模拟通道的创建、打开、关闭、原始码读取和工程量转换；向下完成时钟、引脚、通道选择、启动转换、完成判断、结果读取和必要校准。

ADC 驱动必须区分：

- **必要接口**：所有具备基本 ADC 功能的平台都应实现；
- **特殊接口**：当前平台或当前 ADC 外设具备的额外能力，直接放入 ADC 头文件，并单独分组和说明。

## 2. 必要接口

### ADC 控制器

```c
Int32 TDrvAdcCreate(TDrvAdc *self, const TDrvAdcCfg *cfg);
Int32 TDrvAdcOpen(TDrvAdc *self);
Int32 TDrvAdcClose(TDrvAdc *self);
Int32 TDrvAdcDestroy(TDrvAdc *self);
```

### ADC 通道

```c
Int32 TDrvAdcChCreate(TDrvAdcCh *self, const TDrvAdcChCfg *ch_cfg,
                      TDrvAdc *adc, const TDrvAdcCfg *cfg);
Int32 TDrvAdcChOpen(TDrvAdcCh *self);
Int32 TDrvAdcChClose(TDrvAdcCh *self);
Int32 TDrvAdcChDestroy(TDrvAdcCh *self);
Int32 TDrvAdcChReadOrigValue(TDrvAdcCh *self, Int32 *value);
Int32 TDrvAdcChReadConvValue(TDrvAdcCh *self, Int32 *value);
```

实际项目中函数名应优先保持现有仓库风格。若新平台从零开发，可采用同样的 `TDrvAdc` / `TDrvAdcCh` 命名和生命周期。

## 3. 特殊接口

特殊能力直接增加到 `drv_adc.h`，并放在“特殊功能接口”小节中。例如：

- 硬件校准启动或校准参数写入；
- 多通道扫描；
- 连续转换；
- 外部触发；
- DMA采样；
- 模拟看门狗；
- 内部温度、内部参考或差分输入。

每个特殊接口必须说明适用硬件、调用时机、不支持时返回的通用错误码，以及是否允许在中断中调用。不要求所有平台实现同名特殊接口。

## 4. 配置结构建议

ADC 控制器配置至少应表达：

- ADC 实例索引；
- 参考电压和单位；
- 分辨率或分辨率选择；
- 默认转换超时；
- 平台相关的时钟、端口和复位配置引用。

ADC 通道配置至少应表达：

- 通道号；
- 采样时间；
- 模拟引脚组、引脚号和复用配置；
- 外部分压比例；
- 偏移量和单位。

平台寄存器基址、时钟源、校准寄存器、特殊通道号和寄存器编码属于当前平台实现，可以放在 `drv_adc.c` 的内部配置或本平台私有配置中。

## 5. 标准同步采样时序

```text
检查对象和通道状态
    -> 检查通道号和配置范围
    -> 选择通道
    -> 清除上一次完成/错误标志
    -> 启动转换
    -> 在限定时间内等待完成
    -> 读取原始码
    -> 清理或确认状态
    -> 返回结果
```

不同平台可以使用不同寄存器和等待方式，但必须保证上述语义。任何轮询都必须有超时，超时后必须让 ADC 回到下一次可用的确定状态。

## 6. 工程量转换

对单端 ADC，推荐使用整数公式：

```text
voltage = raw * reference_mv / full_scale
input   = voltage * divider_den / divider_num + offset
```

要求：

- `full_scale`、分压分子和分母不能为 0；
- 乘法使用足够宽的中间类型；
- 对最大输入值进行溢出检查；
- 明确截断、四舍五入和负偏移的规则；
- 输出单位必须写入接口注释。

## 7. ADC 开发步骤

1. 从用户手册和 SDK 梳理 ADC 实例、通道、分辨率、参考源、采样时间、转换时序和校准流程。
2. 以 `demo/drv_adc.h`、`demo/drv_adc_cfg.h` 和 `demo/drv_adc.c` 为起点，保留既有框架和命名。
3. 检查当前平台 `clock`、`port`、`gpio`、`irq`、`dma` 等公共驱动的接口和依赖。
4. 只填写模板平台适配区内的 TODO：实例映射、时钟、复位、引脚、寄存器、校准、状态标志和 SDK 调用。
5. 若当前 ADC 有特殊能力，直接在头文件“特殊功能接口”小节增加接口和注释。
6. 依据项目通用错误码返回参数错误、状态错误、范围错误、超时和硬件故障。
7. 完成正常、异常、边界、重复调用和资源释放验证。

## 8. ADC 模板说明

`demo/drv_adc.h`、`demo/drv_adc_cfg.h` 和 `demo/drv_adc.c` 是 ADC 新平台开发的起点，不是一个需要重新设计的伪代码示例。

- `.h` 保留 `TDrvAdc`、`TDrvAdcCh`、既有公开接口和父对象 `c_ref_`/`o_ref_`；
- `_cfg.h` 保留 `group`、`pin`、`mux`、`x`、`y`、`offset`、`ref_vol`、`spt` 和 `index`；
- `.c` 的“通用框架区”使用父对象引用计数和子对象 `is_open_`，包含生命周期、状态检查和 64 位工程量换算；
- `.c` 的“平台适配区”包含所有 TODO，必须逐项依据用户手册、芯片头文件或厂商 SDK 完成；
- 未完成 TODO 前，平台适配函数返回“不支持”，避免模板被误认为已经具备硬件功能；
- 新平台实现后，可以直接将三文件纳入该平台驱动目录。

## 9. 验证清单

- [ ] 实例索引、通道索引、采样时间和端口范围已校验；
- [ ] 空指针、未创建、未打开、重复打开和重复关闭行为明确；
- [ ] 时钟、复位、引脚、寄存器初始化顺序正确；
- [ ] EOC标志、错误标志和启动标志处理正确；
- [ ] 转换超时后硬件状态可恢复；
- [ ] 校准失败、校准超时和校准数据异常有明确返回；
- [ ] 接地、满量程、参考电压和已知输入值验证通过；
- [ ] 分压分母为 0、乘法溢出和负偏移已验证；
- [ ] 多通道共享控制器时引用计数和打开关闭语义正确；
- [ ] 关闭后时钟、引脚和中断状态正确恢复。

## 10. 现有 ADC 实现的重点改进项

以下是基于现有代码结构得出的通用问题，不涉及某个具体 MCU 的寄存器设计：

### P0

1. 通道创建接口必须完整检查控制器配置指针，并验证实例索引，避免空指针和配置数组越界。
2. 控制器和通道打开/关闭时必须检查父对象操作结果，不能忽略失败后继续访问硬件。
3. 重复关闭等错误分支不能被后续正常分支覆盖，必须保证返回值和状态一致。
4. 通道号、采样时间、端口和所有数组索引必须在寄存器操作前校验。

### P1

1. 校准计算必须检查转换超时、采样结果有效性和除数为 0。
2. 原始码转换必须根据实际分辨率计算满量程，并使用宽位宽中间值。
3. 通道销毁是否自动关闭必须明确，并与其他驱动保持一致。
4. 控制器/通道引用计数的所有权和最终关闭时机必须写入接口文档。
