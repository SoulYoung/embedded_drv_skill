# Flash 驱动模块开发规范

## 1. 模块职责

Flash 驱动提供存储区域信息、读、写、擦除和校验；分区、保护和认证等为特殊能力。

## 2. 必要接口

- `TDrvFlashCreate/Destroy/Open/Close`
- `TDrvFlashGetInfo`
- `TDrvFlashRead/Write/Erase/Verify`
- `TDrvFlashEraseBlock/EraseAll`

demo 已定义的分区、信息区、保护、认证、交换区和特殊写入模式等接口同样属于公开框架。平台实现必须保留其声明；目标硬件不支持时，按接口约定返回明确的不支持错误。目标芯片新增的能力放在“特殊接口”分组中，并完整说明硬件作用域。

## 3. 实现规则

1. 依据手册确认存储区域、编程粒度、擦除粒度和各操作的作用范围。接口和注释应区分编程单位、擦除单位与硬件存储组织，避免沿用含义不一致的术语。
2. 地址和长度校验必须避免算术溢出，并覆盖不连续区域、对齐要求及硬件规定的跨边界限制。
3. 写擦前满足目标控制器要求的全部前置条件，例如工作状态、保护状态、时钟或时序配置；相关依赖变化后应重新确认这些条件。
4. 从手册还原目标控制器的命令状态机，包括准备、参数传递、启动、等待、结果判断和收尾。参数通过寄存器、存储映射地址还是内部缓冲区传递，以及是否需要解锁、同步或清状态，均由目标硬件决定。
5. 寄存器写法必须符合访问属性和副作用；数据访问宽度、次数和对齐必须符合目标控制器要求。所有可能无法结束的等待都应有超时和明确错误返回。
6. 若手册限制命令期间的取指或数据访问，应验证完整调用链、只读数据、回调和中断路径均位于允许访问的区域，并通过链接配置和最终产物确认实际放置。
7. 临界区只覆盖并发一致性或硬件原子时序真正需要保护的范围。是否需要覆盖整个操作等待期，应依据中断路径能否访问忙存储区、硬件是否支持并行读写及项目实时性要求判断。
8. demo 已有的特殊接口必须保留。目标 MCU 不支持时，完成参数和对象状态检查后返回现有不支持错误码；目标 MCU 确有独有能力且上层需要时，增加到“特殊接口”分组。若既有接口抽象与目标硬件能力不一致，先完成接口语义审计。

## 4. 验证清单

- [ ] 读写擦除边界、非对齐请求和非法区域处理正确。
- [ ] 擦除后、写入后和校验失败的状态符合手册。
- [ ] 若实现了扩展能力，其状态和副作用不会意外影响普通读写路径。
- [ ] 每个有效区域的首尾、最小操作单位、完整区域以及相邻不连续区域均做边界测试。
- [ ] 目标控制器要求的命令前置条件、完成条件、错误状态和收尾动作均已覆盖。
- [ ] 若存在执行区域限制，最终链接产物中的代码和只读数据放置符合手册要求。
- [ ] 目标芯片能力表能够证明每个公开接口的作用域；不支持能力返回明确错误。
